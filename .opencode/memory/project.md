# office-auto — Project Memory

## Identity
MCP server for Markdown-to-DOCX document generation via OfficeCLI.
LLM makes decisions (action_decisions), deterministic code compiles to OfficeCLI ops.

## Architecture
- **MCP Server**: `mcp/office-auto-server.ts` — StdioServerTransport
- **4 Tools**: inspect_template, compile_ops, execute_ops, validate_output
- **LLM Model**: Qwen3-35B-A3B-GGUF (256K context, MoE 3.6B active)
- **CLI Dependency**: `officecli` binary must be in PATH

## Key Files
- Template: `format_template.docx`
- Content: `noidung.md`
- Intent: `intent.json` (auto-generated by LLM, not pre-existing)
- Output: `output_YYYYMMDD_HHMMSS.docx`

## Data Flow
User → Orchestrator agent → MCP tools → OfficeCLI → output.docx
Each tool logs artifacts to `runs/{timestamp}/`.

## Conventions
- Template is never mutated — always copied to output
- All officecli calls use spawnSync (no shell injection)
- LLM never writes paraIds, paths, or commands — compile_ops handles all mapping
- Qwen3 35B has 256K context — single-pass processing, no chunking needed
